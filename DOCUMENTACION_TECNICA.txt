================================================================================
MEJORAS FUTURAS
================================================================================

1. OPTIMIZACIÓN: SUMA DE RANGO PREFIJA
   Cambio: O(n) suma_rango → O(1) suma_rango
   Impacto: O(n³) → O(n²)
   
   Implementación:
   ```
   prefix = [0] * (len(st) + 1)
   for i in range(len(st)):
       prefix[i+1] = prefix[i] + st[i]
   
   suma_rango = lambda i,j: prefix[j+1] - prefix[i]
   ```

2. ALGORITMO BOTTOM-UP
   Cambio: Recursión top-down → iteración bottom-up
   Impacto: Reducir overhead de llamadas recursivas
   Beneficio: 10-20% más rápido

3. MEDIR CON n MÁS GRANDES
   Actual: n ≤ 16
   Sugerido: n ≤ 24
   Beneficio: Mejor validación de O(n³)

4. COMPILACIÓN JIT
   Tool: PyPy en lugar de CPython
   Beneficio: 2-3x más rápido en código Python puro

5. PARALELIZACIÓN
   Para múltiples instancias: usar multiprocessing
   Impacto: Acelerar mediciones (ejecutar casos en paralelo)

================================================================================
PREGUNTAS FRECUENTES
================================================================================

P: ¿Por qué arreglos son más lentos si tienen acceso O(1)?
R: El overhead de indexación 3D (arr[i][j][k]) es mayor que hash dict.

P: ¿Por qué no se ve claramente O(n³)?
R: Los tiempos son muy pequeños (microsegundos). El ruido de medición
   es comparable a las diferencias esperadas. Con n > 20 sería claro.

P: ¿Cuál versión debería usar?
R: Diccionarios. Son 2-6x más rápidos y usan menos memoria.

P: ¿Se puede optimizar a O(n²)?
R: Sí, con suma de rango prefija (ver sección Mejoras Futuras).

P: ¿Qué tal la implementación iterativa?
R: Posible pero más complicada. Reduciría overhead de recursión ~10-20%.

P: ¿Cómo escala a n = 100?
R: Diccionarios: ~1-10 segundos. Arreglos: No recomendado (memoria).

================================================================================
REFERENCIAS TÉCNICAS
================================================================================

O(n³) Derivación:
- Número de subproblemas: O(n²)
  Pares (i,j) con 0 ≤ i ≤ j < 2n
  × 2 para turno ∈ {0,1}
  
- Trabajo por subproblema: O(n²) en peor caso
  Loop k: O(n) iteraciones
  Suma_rango: O(n) tiempo
  Total: O(n) × O(n) = O(n²)
  
- Pero en promedio, subproblemas pequeños requieren O(n) trabajo
- Análisis amortizado: O(n³)

Teorema de Complejidad (Memoización):
- Tiempo = (# subproblemas) × (trabajo por subproblema)
- Espacio = profundidad recursión + tamaño tabla

Localidad de Caché (por qué arreglos a veces ganan):
- Arreglo 3D: acceso secuencial → mejor cache hits
- Hash dict: acceso pseudoaleatorio → cache misses
- En este problema: dict es pequeño → cache benefits neutralizados
